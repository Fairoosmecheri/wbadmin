# Architecture decisions

- **Modular monolith:** Next.js route handlers validate input and call feature services. PostgreSQL is the single system of record. The independent worker shares domain modules rather than introducing another service API.
- **Prisma 7:** mature PostgreSQL ORM with committed migrations and transactions. The development cloud blocks its native binary CDN, so an explicitly pinned official WASM migration/generation helper is supplied. Runtime uses Prisma's PostgreSQL adapter. No TLS, artifact, or migration checksum verification is disabled.
- **Better Auth:** maintained stable email/password authentication with scrypt password hashing, database sessions, disabled public registration, and database-backed login throttling. `Account.password` is the auth library's hash field; duplicating a hash on `User` would create competing sources of truth.
- **Server authorization:** every CRM API authenticates a session. Role changes/deactivation are re-read from the database. Salesperson customer scope and assigned follow-up restrictions live on the server. Credential storage never enters client props.
- **Mutations:** cookie-authenticated API requests require the configured Origin. Webhooks use their own signature and account checks. Prisma supplies parameterized queries; raw queue/timeline SQL uses bound parameters.
- **Customer integrity:** E.164 normalization precedes duplicate checks. The database enforces uniqueness across archived and active customers. Consent and opt-out are independent evidence fields; stale updates must not re-enable contact. Archival preserves communication history.
- **Imports:** bounded files, ZIP expansion inspection, no spreadsheet formula evaluation, paginated preview, explicit duplicate strategy, immutable validation token, stale-review checks, transactional commit, persisted report. Export neutralizes formula prefixes.
- **Segments:** validated JSON filter definitions are evaluated against current customers. Personal saved views have ownership. Campaign launch snapshots eligible recipients; later customer changes do not add new recipients.
- **Sending:** approved text templates, preview/test/confirmation, immutable recipient payloads, per-recipient uniqueness, PostgreSQL row locks, lease recovery, and shared rate clock. Mode/template fingerprints prevent a previously reviewed mock payload from becoming a real send.
- **Delivery ambiguity:** no distributed transaction exists between PostgreSQL and Meta. Unknown outcomes are held for review rather than automatically retried; the UI never promises external exactly-once delivery.
- **Webhooks:** raw HMAC verification, configured account scoping, event/message uniqueness, monotonic status progression, transactionally updated metrics, and replay of events that race outbound persistence. Unknown contacts require review.
- **Mock mode:** a provider implementation that writes durable simulated events and performs no Meta calls. It exercises the same inbound/status path as the live adapter.
- **Performance:** server pagination and bounded exports, bulk inserts, aggregation in PostgreSQL, indexed relationships, no per-customer browser fetch of the entire database. Offset pagination is used for human-sized table pages; messaging and queue operations use bounded batches. Reassess search indexes with representative production query plans at 50,000+ records.
- **Dependency security:** csv-parse is on its patched stable major. Narrow overrides update Prisma tooling's deepmerge-ts/mysql2 and ExcelJS's UUID dependency; validate generation, migrations, imports, exports, and tests when refreshing them.
- **V1 media:** retain inbound type/media identifiers and captions safely. No arbitrary media URL fetch is exposed. Download/storage, media-header templates, and dynamic button parameters require additional explicit implementation.
